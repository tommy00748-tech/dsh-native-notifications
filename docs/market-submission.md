# Listing this plugin in DSH plugin markets

DSH has **no vendor-hosted plugin index**: "market" is a set of index URLs a user adds under
**Settings → Plugins → Discover → Index sources**, each serving one JSON document in **plugin market index
format 1**. This repository supports every practical listing path.

## 1. npm (feeds the crawlers)

Publishing the package is the main distribution step, because several community indexes are generated by
crawling npm for packages that declare `dsh.bundle.patch`:

```sh
npm publish --access public        # or push a v* tag; .github/workflows/publish.yml does it
```

After the package is live, these indexes pick it up on their next crawl without any pull request:

- `https://jingjiangze.github.io/dsh-market/index.json` (npm crawler)
- `https://hoyyang.github.io/dsh-market-index/index.json` (GitHub `#dsh-plugin` crawler)
- the registry behind `ChasePassion/dsh-plugin-marketplace`

## 2. This repository's own index source

`index.json` at the repository root is a valid format-1 index that lists this plugin:

```
https://raw.githubusercontent.com/tommy00748-tech/dsh-native-notifications/main/index.json
```

Add it in DSH under **Settings → Plugins → Discover → Index sources** (or with the `plugin_market` agent
tool API). The DSH fetch refuses redirects, so use the `raw.githubusercontent.com` URL above (it answers
directly), not a GitHub HTML URL.

Regenerate the entry after a release: the version's `publishTimestamp` must be integer seconds and the
`version` must be exact SemVer. `node scripts/check.mjs` validates the document locally.

## 3. DSH Plugin Hub (dsh-plugin.org)

The community hub lists 5,000+ npm packages, human-reviewed, and is the catalog the `dsh-plugin`
marketplace app reads. Submit the published package at:

<https://dsh-plugin.org/zh/submit>

The hub reviews repositories, not npm alone. Its checklist:

- the repository is **public** and its README states what the plugin does and how to install it;
- the repository carries the GitHub topic **`dsh-plugin`** (the scanner uses it);
- the README contains a copy-paste install command of the form
  `dsh plugin --profile web add <package-name>` (this repo lists both `web` and `desktop`);
- the plugin exports `apply(ctx)` and keeps a root `package.json` with the package name and version;
- a clear license (this repo is MIT) plus supported profile, permissions and compatibility notes;
- for the in-app plugin centre the package must also exist on npm.

Have ready: npm package name (`dsh-native-notifications`), repository URL, one-line description (EN/ZH),
category (Interface / 界面体验) and labels (Notifications).

## 4. Community index pull requests

Some indexes accept hand-written entries. When opening such a PR, paste this entry into the target
index's `plugins` array (and declare `ui` / `notifications` / any sort key in `metadata` if the target
document uses them):

```json
{
  "name": "dsh-native-notifications",
  "title": {
    "en": "Native Desktop Notifications",
    "zh": "桌面通知"
  },
  "description": {
    "en": "Native desktop notifications from DeepSeek Harness itself: approval requests, questions, finished tasks, errors and sign-in prompts. Banners are attributed to the DSH app, a click focuses DSH and opens the conversation, and the chime can be chosen from presets or authored as a note sequence.",
    "zh": "由 DSH 自己弹出的原生桌面通知：需要确认权限、等待作答、任务完成、执行出错、需要登录时提醒你。通知归属于 DeepSeek Harness 应用，点击回到 DSH 并打开对应会话；提示音可选预设或自定义音高序列。"
  },
  "author": "tommy00748-tech",
  "homepage": "https://github.com/tommy00748-tech/dsh-native-notifications#readme",
  "repository": {
    "url": "https://github.com/tommy00748-tech/dsh-native-notifications"
  },
  "category": "ui",
  "labels": [
    "notifications"
  ],
  "icon": "https://raw.githubusercontent.com/tommy00748-tech/dsh-native-notifications/main/icon.svg",
  "versions": [
    {
      "version": "1.0.0",
      "publishTimestamp": 1793872492,
      "engines": {
        "dsh": ">=0.1.0"
      },
      "source": {
        "type": "npm"
      }
    }
  ]
}
```

Validator rules worth restating (they reject the whole document, not one entry):

- every `category` and `label` id used by an entry must be declared in `metadata`;
- `version` is exact SemVer, `publishTimestamp` is integer seconds;
- optional string fields must never be empty (`author: ""` fails);
- `repository.url` and `source.registry` are absolute URLs without query or fragment;
- package names must be unique in the document.

## 5. Direct GitHub install (no market needed)

The bundle is directly installable from this repository:

```sh
dsh plugin --profile desktop add github:tommy00748-tech/dsh-native-notifications
```
